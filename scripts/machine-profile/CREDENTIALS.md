# Credentials a machine needs (names only; values come from the AI Matrx Vault)

No value is ever committed. The setup script installs nothing secret.

## Logins (human, once per machine)
`gh auth login` · `vercel login` · Claude Code / Codex sign-in · Supabase MCP OAuth per account (see `common-docs/systems/architecture/agent-machine-setup/FEATURE.md`).

## Per-repo `.env` files (gitignored)
The variable names are the committed templates: `aidream/.env.example`, `matrx-frontend/.env.example`, `matrx-local/.env.example`, `matrx-extend/.env.example`, `matrx-ship/.env.example`, `matrx-sandbox/.env.example`. Copy each to `.env` and fill from the vault. Test-account sign-in uses `AI_ADMIN_USERNAME` and `AI_ADMIN_PASSWORD` from the `.env` of `aidream` or `matrx-frontend`.

## Machine-level values stripped from the committed config
| Name | Where it lives on a machine | Source |
|---|---|---|
| `SUPABASE_ACCESS_TOKEN` | `env` block of `~/.claude/settings.json` | vault (Supabase access token) |
| `WP_API_URL`, `WP_API_USERNAME`, `WP_API_PASSWORD` | `[mcp_servers.allgreen-wordpress.env]` in `~/.codex/config.toml` | vault (All Green WordPress) |
| `NODE_REPL_*`, `SKY_CUA_SERVICE_PATH`, `CODEX_CLI_PATH`, desktop `accountId`/`userId` | `~/.codex/config.toml` | host-generated by the Codex app, not copied |

## Local key files (`~/Code/secrets/`, never committed)
AWS admin access-key CSV, sandbox SSH `.pem` keys, and the provider folders (apple, chrome-web-store, cloudflare, cohere, fastino, google, supabase, and others): copy from the vault.

`~/.claude/settings.json` and `~/.codex/config.toml` are installed only when absent and never replaced, because each machine adds its own credentials to them.
